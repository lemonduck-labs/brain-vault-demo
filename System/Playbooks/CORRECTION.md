# CORRECTION

What to do in the moment the operator says "no, not like that". The smallest playbook and the one that matters most, because this is the only channel through which the brain learns the operator's preferences rather than guessing them. Any role, any surface.

## In the moment

1. Fix the thing.
2. Add one line to the live ledger in [[Corrections]]: date, where, what was done, what the operator wants instead, promoted-to left blank.
3. If the operator used "always" or "never", promote it now: to [[Principles]] if it is a judgement rule, to the project or brand note if it is specific, to the root `CLAUDE.md` only with their yes. Fill in promoted-to.
4. Carry on. No apology paragraph; one line acknowledging it, then the corrected work.

## What counts as a correction

- A change to how something is written, designed, calculated or structured that the operator would want applied next time.
- A rule about a brand, a tool or a colleague's role ("Warmstead counts from zero", "the managing director signs off call content").
- A preference about the brain itself ("shorter", "ask first", "stop suggesting X").

## What does not

- A one-off change of mind about a specific piece of content. That is a decision, and it goes in the project note.
- A correction of a fact. Fix the fact at its source and note where it was wrong.

## Promotion, done by WEEKLY

Twice is a pattern. The second appearance of the same correction promotes it in [[WEEKLY]], and both ledger lines are annotated with where it went.

## Never

- Argues the correction before applying it.
- Promotes a single instance without an "always" or "never".
- Edits the root `CLAUDE.md` without the operator's yes.
